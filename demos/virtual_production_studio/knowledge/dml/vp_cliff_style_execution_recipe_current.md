# VP Studio agentic execution recipe

VP execution recipe: use the working Cliff House phase pattern with the VP brief
and `prompts/01a_locked_scene_manifest.md`, keep the existing Rhino slot, and
create one coherent manifest-defined assembly per Rhino MCP mutation, followed
by targeted corrections supported by inspection. Do not impose a call or turn
quota; let the agent recover naturally as in the original Cliff House. Print every
constituent object's world bounds after mutation. Stay inside the current phase,
inspect recognizable subassemblies, capture a viewport for concrete vision review,
correct defects, and save an accepted phase checkpoint through `save_doc`. Use the
direct metadata-bearing `.3dm` Blender handoff. Daystrom DML supplies automatic
continuity and useful prior successes/failures; it advises the agent and does not
control ordinary geometry operations.

For Rhino, use the existing launcher-owned slot and datum template. Geometry
mutations use only `mcp_rhino_run_csharp(script=...)`, copying the tested C#
scaffold embedded in the current phase prompt. Treat every `Objects.Add*`
result as a `Guid`; construct absolute WorldXY geometry once and do not apply a
second translation. Python is read-only inspection/capture through
`mcp_rhino_run_python`. Never execute Rhino Python/C# outside those MCP tools. Never
preload later phases. At each phase review gate, inspect names, world bounds,
containment, layers, metadata and geometry; only after numeric PASS review a
fresh viewport with vision, then make targeted
corrections, then save one checkpoint. Do not model electrical, HVAC, data, or
fire-protection systems; write only the compact estimated-load note required by
the brief.

Avoid whole-studio builders, one-object call loops, checked-in builders,
`open`/`compile`/`exec` script loaders, fixed-count DML checkpoints, interactive
Rhino New/Save/Export commands,
duplicate slots, document close/reopen recovery, and unrelated browser or shell
fallbacks. At a real failure, inspect actual application state, retrieve the
prior failure pattern, and change the approach.

For Blender, use the metadata-preserving direct `.3dm` handoff and the shared
importer. Preserve all joined render-mesh parts, metadata, units, and bounding-box
parity before visual work.
