# Cliff House demo operator contract

This demo runs as `project:cliff-house-01` with isolated Daystrom stores. Use Rhino MCP for authoritative architectural geometry, Blender MCP for metadata-preserving visualization work, and ComfyUI only for stylizing approved renders.

Before consequential work, call `mcp_daystrom_dml_stats`, query for this phase and operation, then call `mcp_cma_augment`. Inspect application state before mutation, make one bounded change through the configured MCP server, and inspect again. Ingest a structured success or failure record after the attempt. Call `mcp_cma_reinforce` only for an objectively validated success.

Use the existing ready Rhino slot; do not spawn a replacement. Prefer scripted `mcp_rhino_run_python`/`mcp_rhino_run_csharp`, never interactive Export/Save macros, and use `mcp_rhino_save_doc` only at a passed gate. Handoff to Blender as a metadata-bearing `.3dm` with render meshes through `../../skills/import_with_metadata.py`; OBJ and FBX are prohibited. Validate through `../../skills/validate_blender_scene.py` before advancing.

Do not repeat an approach recorded as failed without a material change. If DML or an application MCP is unavailable, preserve state and stop at the gate.
